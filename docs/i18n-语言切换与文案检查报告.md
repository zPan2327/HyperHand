# 语言切换与国际化检查报告

> 2026-11-27 / 3.4.6 之后的新增改动。范围：语言开关（个性化 → 语言）+ 资源级国际化。

## 1. 新增功能

设置页最底部新增「个性化」分组，组内只有一行「语言」：

| 选项 | 对应资源目录 | 说明 |
|---|---|---|
| 跟随系统 | —（清空应用级 locale） | 交还给系统语言设置 |
| 简体中文（默认） | `res/values/` | 默认值，不跟随系统 |
| 繁體中文 | `res/values-b+zh+Hant/` | |
| English | `res/values-en/` | |

实现要点：

- 走 **Android 13+ 的应用级语言**（`LocaleManager.setApplicationLocales`，`minSdk = 33` 正好可用），
  不自己包 Context、不改 `Configuration`；系统负责重建 Activity 并切资源。
- 偏好存 `SharedPreferences("hyperhand_ui")`；启动时 `Lang.applyOnStart()` 对齐一次——
  首次安装偏好是 `zh-Hans`，系统里是空，因此「默认简体中文」对系统语言是英文的用户同样成立；
  之后只有两者不一致才写，不会每次冷启都重建 Activity。
- 「跟随系统」= 传 `LocaleList.getEmptyLocaleList()`，即清空应用级设置。
- 顺手修了一个连带问题：语言切换会重建 Activity，原来会被 intent 里的初始 tab 拉回「概览」。
  现在 `onSaveInstanceState` 存当前页码，重建时优先恢复，用户还停在「设置」页。

## 3. 关键发现：文案 98% 是硬编码

`strings.xml` 原本只有 2 条（`app_name`、`app_description`），界面文案几乎全部写死在代码里。
按当前代码统计（去掉注释后统计含中文的字符串字面量）：

| 处数 | 去重 | 文件 |
|---|---|---|
| 108 | 105 | `SettingsPage.java` |
| 79 | 69 | `MainActivity.java` |
| 72 | 66 | `AboutPage.java` |
| 47 | 46 | `glass/.../dialogs/DialogStrings.kt` |
| 44 | 44 | `smartkey/ui/UiHelpers.kt` |
| 34 | 31 | `Cfg.java` |
| 26 | 17 | `smartkey/ui/SkRows.kt` |
| 22 | 22 | `smartkey/ui/EditRuleScreen.kt` |
| 21 | 20 | `OverviewPage.java` |
| 20 | 20 | `Recognizer.java`（含日志/诊断串） |
| 20 | 19 | `smartkey/ui/HomeScreen.kt` |
| 15 | 15 | `smartkey/ui/StatusScreen.kt` |
| 11 | 10 | `smartkey/ui/AppPickerScreen.kt` |
| 其余 17 个文件 | ≤8/文件 | 零散 |
| **合计** | **564 处** | |

**因此当前切换语言只会影响「个性化」这一块**（它是唯一走资源的部分），其余页面仍是中文——
这是资源化的覆盖度问题，不是开关失效。要让整页跟随语言，必须把文案抽到 `strings.xml`。

## 4. 抽取计划（建议分三步）

1. **设置页 + 概览 + 关于**（`MainActivity` / `SettingsPage` / `OverviewPage` / `AboutPage` / `Cfg`，约 314 处）：
   这几个文件里 `c`（Context）都在作用域内，替换成 `c.getString(R.string.xxx)` 最直接；
   需要单独处理的是 6 处字符串拼接（` 条规则`、`系统原生 ` 等），改成带占位符的完整句子。
2. **Compose 按键映射页**（`UiHelpers` / `SkRows` / `HomeScreen` / `EditRuleScreen` / `StatusScreen` / `AppPickerScreen`，约 138 处）：
   文本在 `@Composable` 内换 `stringResource(R.string.x)`；`KeyType.label`、`ConditionType.label`
   这类数据层扩展属性要改成 `@Composable get()` 或改成传 `Context` 的普通函数。
3. **诊断/日志串**（`Recognizer`、`HyperHand`、`hook/*`）不建议翻译：它们是写进 `Settings.Global`
   供调试读的，翻译反而增加对不上的风险，可标 `translatable="false"` 或保持原样。

每步完成后按同一口径复核：key 集合三份一致、占位符类型与数量一致、`translatable="false"` 不被翻译。

## 6. 第一步完成情况（2026-11-27）

### 已抽取

| 文件 | 抽取条数 | 处理方式 |
|---|---|---|
| `SettingsPage.java` | 102 | 字面量 → `c.getString(R.string.set_xxx)`；3 处拼接串改成带占位符的整句 |
| `Cfg.java` | 31 | `static final String[]` → `xxxNames(Context)` 方法（静态数组没法跟随语言） |
| `MainActivity.java` | 75 | 字面量 → `getString(...)`；`ago()` 由静态改实例，时间片段改成 `%1$d 分钟前` 这类整句 |
| `OverviewPage.java` | 21 | 同上；静态 `safe()` 改实例 |
| `AboutPage.java` | 72 → 3 | 三段长文本（引用/使用说明/许可）各自合并成**一条**资源，不再逐行拼接 |
| `AnimCtl.java` | 4 | 写进 `Settings.Global` 的诊断串改用 `anim_info_*` 四条带占位符的资源 |

配套代码改动：`Cfg` 新增 `animCurveShort(c)` / `modeShort(c)` / `topSideNames(c)` 等取值方法，
并加了 `ANIM_CURVE_COUNT` / `TOP_SIDE_COUNT` / `MODE_COUNT` 常量（原来靠数组 `.length` 判越界）。

### 踩到的坑

1. **静态数组无法国际化**：`Cfg` 里那几组文案是 `static final String[]`，只能改成传 `Context` 的方法，
   再把 4 个调用点（Settings/About/MainActivity/AnimCtl）一起改。
2. **aapt 对裸 `%` 报错**：`10% 时间走完 50% 位移` 这类文案必须标 `formatted="false"`，
   否则会被当成多参数格式串；带 `%1$d` 的则不能标。
3. **多行文案要转义**：XML 里直接写裸换行会让 aapt2 报
   `Invalid unicode escape sequence`，统一换成 `\n`。
4. **字符串拼接片段**：`" 条规则"`、`" 分钟前"`、`"（固定高度）"` 这类片段单独翻译会读不通，
   都改成了带占位符的完整句子（`%1$d 条规则`、`%1$d 分钟前`）。

## 7. 第二步完成情况（Compose / :glass 模块）

### 资源放在哪

`:module` 依赖 `:glass`，反向不可见，所以 Compose 代码引用不到 `:module` 的 `R`。
第二步给 `:glass` 建了自己的资源目录：

```
glass/src/main/res/values/strings.xml          （默认 = 简体）
glass/src/main/res/values-en/strings.xml
glass/src/main/res/values-b+zh+Hant/strings.xml
```

两个模块的资源最终合并进同一个 APK，互不影响。

### 抽取结果

| 文件 | 处理 |
|---|---|
| `UiHelpers.kt` | `KeyType.label` 等 6 个扩展属性拆成两份：`label(c: Context)`（给普通函数用）+ `@Composable val label`（给 Compose 用，内部走 `LocalContext`），调用点一行没动 |
| `SkRows.kt` / `HomeScreen.kt` / `EditRuleScreen.kt` / `StatusScreen.kt` / `AppPickerScreen.kt` / `ConditionPicker.kt` | 字面量全部换成 `stringResource(R.string.sk_xxx)`，共 93 条 |
| 5 个 `Sk*Activity.kt` + `ModuleStatus.kt` | 同上（`ModuleStatus.detect` 里改用 `context.getString`） |
| `HyperGlassBarView.kt` | 底栏「概览 / 设置 / 关于」改为 `defaultItems(context)` 取资源 |
| `MiuixNumberPickerHost.kt` | 取消 / 确定走资源 |
| `RuleRepository.kt` | 「（副本）」后缀走资源 |

### 三个新坑

1. **模板串不能当普通文案抽**：`"按下「${mapping.key.label}键」时执行"` 直接换成 `stringResource(…)`
   会把插值丢掉。这 10 条改成带占位符的资源（`%1$s键 · %2$s`），调用点补参数。
2. **非 composable 上下文**：`onClick` 回调、`object S` 常量、数据类里都不能调 `stringResource`，
   分别改成 `getString(...)` / `context.getString(...)`。
3. **首尾空格会被 aapt 裁掉**：`" (%1$s)"`、`"System UI "` 这类必须写成 `" (%1$s)"`（整串加引号），
   否则英文会粘成 `App is playing(YouTube Music)`。

## 8. 收尾：清理 SonyPods 残留代码（2026-11-27）

第二步留下的「有意不翻」清单里，那批 SonyPods 耳机弹窗在 HyperHand 里没有任何入口，
属于复制过来后没用上的死代码，本轮直接删除。

### 删了什么

| 文件 | 内容 |
|---|---|
| `glass/dialogs/SimpleDialogs.kt`（284 行） | 6 个耳机弹窗：`PowerOffDialog`、`SafeListeningRootHelpDialog`、`LdacEnableConfirmDialog`、`ConnectionQualityConfirmDialog`、`MultipointAlertDialog`、`AncCycleModesDialog` |

删除前逐个确认过调用方：7 个 Composable 在全仓库只出现在注释里（0 处实际引用）。

### 保留的部分（不是死代码）

- `RestartScopeDialog.kt` —— 概览页右上角的重启按钮在用；
- 其宿主类 `SonyPodsDialogHost` 改名为 **`RestartScopeDialogHost`**，因为它现在是这个弹窗的专用桥接，
  跟 SonyPods 已无关系（`MainActivity` 里的全限定引用同步改）；
- `object S` 里仍在用的 4 条文案（重启作用域标题/正文、取消、确定、知道了）改成资源
  `sk_restart_scope_title`、`sk_restart_scope_summary`、`sk_061`、`sk_141`、`sk_got_it`，
  于是 `DialogStrings.kt` 可以整份删掉。

### 顺手补的两处遗漏

1. **`about_license` 三语都是中文**：英文界面下许可对话框显示的是中文 MIT 译文。
   现在 `values-en` 只放英文原文，`values-b+zh+Hant` 放繁體译文 + 英文原文，默认简体保持原样。
2. **6 个 Activity 的 `android:label` 写死中文**（最近任务里可见）：
   `按键映射 / 运行状态 / 编辑规则 / 添加触发条件 / 选择应用 / 按键自检`
   → `@string/activity_*`；`Ui.confirmDialog` 的「取消」→ `@string/dialog_cancel`。

### 本轮踩的坑

写多行许可文本时，转义层数算错导致正文里出现字面量 `//n`（`conditions://n//nThe above…`）。
修法：用 `NL = chr(92) + "n"` 显式拼装再写文件，写完立刻回读校验
（`反斜杠n` 计数、`//n` 计数、真实换行计数），六个 strings.xml 全量扫一遍确认无残留。

### 最终剩余：32 处中文（全部在调试链路）

| 文件 | 处数 | 说明 | 处理 |
|---|---|---|---|
| `Recognizer.java` | 20 | 手势判定原因的说明文字（「下滑距离太短」等），设置页**调试模式**下的「下滑诊断」展示 | 未翻 |
| `HyperHand.java` | 8 | 「超出区线 12 dp，可增大触发区高度」这类距离提示，同上，且写进 `Settings.Global` 供 adb 比对 | 未翻 |
| `GlassBar.java` | 3 | 旧版悬浮底栏的 `LABELS`，类注释已写明「已不再被 MainActivity 使用，保留作对照与回滚」 | 未翻（死代码） |
| `SkSelfTest.java` | 1 | 自检用例名 `combo all4 / 4 taps -> double x2`，只进 logcat | 未翻 |
