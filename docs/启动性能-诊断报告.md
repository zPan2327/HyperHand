# HyperHand 启动性能诊断报告（2026-11-24）

设备：Xiaomi 14 / houji / Android 16 (API 36) / 1200×2670 / 480dpi / 120Hz LTPO  
版本：3.3.4 (30304)，`module` 主界面（Java View 外壳 + 4 个 Compose 宿主）  
方法：临时在 `MainActivity` 各阶段插入 `System.nanoTime()` 打点（`HHPERF` 标签），  
配合 `am start -W`、`dumpsys gfxinfo`、`ViewTreeObserver`（doFrame / layout / onDraw /  
preDraw）逐点定位；对照组通过新增 `fast` buildType（与 debug 同代码、同签名，  
仅 `debuggable=false`）拿到 ART 的 AOT 编译。

---

## 1. 结论先说

1. **不是资源问题**。启动期 GPU 每帧 4～6ms（`50th gpu percentile 4ms`，  
   `90th 6ms`），面板 120Hz 预算 8.3ms，没有 GPU 拥塞；内存常驻  
   `TOTAL PSS 173MB`（Graphics 54MB / Native 36MB / Java 13MB），不属于压力水平；  
   也没有热降频迹象。掉帧的原因是**主线程同步做完太多初始化**，是纯代码耗时。
2. **但最大的一个放大器是包本身**：一直装的 `module-debug .apk` 带  
   `debuggable=true`，ART 对这种包**跳过 AOT 编译**（安装后  
   `dumpsys package` 显示 `status=run-from-apk` / `verify`，`oat/arm64/base.odex`  
   只有 148KB）。同一份代码换成非 debuggable 包后 `base.odex` 变成 44MB，  
   **冷启动总耗时从 1330ms 降到 425ms，首帧从 720ms 降到 200ms**。

| 指标（3 次冷启动）                | debug（无 AOT）          | fast（AOT speed）    |
| ------------------------- | --------------------- | ------------------ |
| `am start -W` TotalTime   | 1320 / 1339 / 1396 ms | 421 / 422 / 429 ms |
| 首帧 `onDraw`（自 onCreate 起） | 694 / 722 / 729 ms    | 189 / 190 / 222 ms |
| `onCreate` 结束             | 228 / 253 / 258 ms    | 66 / 68 / 80 ms    |
| gfxinfo 90th 帧            | 600～650 ms            | 200 ms             |
| Janky frames              | 3～4（8～12%）            | 2（5%）              |
| Number Slow UI thread     | 3～4                   | 1                  |

> 用户看到的「启动掉帧」= 首帧本身花了 600～700ms，系统转场动画在等这一帧。

---

## 2. `onCreate` 分段（debug 包，约 250ms）

| 阶段                                            | 耗时         | 说明                                                                         |
| --------------------------------------------- | ---------- | -------------------------------------------------------------------------- |
| `super.onCreate` + `actionBar.hide()`         | **51ms**   | 框架：Activity attach、装 DecorView、解析主题                                        |
| `Theme.colors()`                              | 0.4ms      | 只是拼整数色值，可以忽略                                                               |
| `Cfg.get()`                                   | **14.5ms** | SharedPreferences 首次加载（XML 解析）                                             |
| `OverviewPage`                                | **34ms**   | `Ui.page` 4.7 + `build()` 14 + `refresh()` 14（内含 Compose `StatusCardHost`） |
| `SettingsPage`                                | **87ms**   | 构建 **252 个 View**（整页所有 preference 行）                                       |
| `AboutPage`                                   | **31ms**   | 其中 `MiuixBg`（全屏流动背景）4.3ms                                                  |
| `HyperGlassBarView`                           | 9～13ms     | 液态底栏（Compose）                                                              |
| `MiuixDropdownHost` + `MiuixNumberPickerHost` | 3ms        | 两个全屏透明弹窗宿主（Compose）                                                        |
| `PagePager` + `TopBar` + `selectTab`          | 15ms       |                                                                            |

**三页在 `onCreate` 里全部构建**（`buildShell()` 一次性 `new` 三个页面），  
其中设置页 252 个 View 占了三分之一；但在 AOT 下这段只有 66～80ms，  
说明 debug 包的类加载/解释执行把纯 View 构建放大了约 4 倍。

---

## 3. 首帧遍历拆分（debug 包，约 430～500ms）

从 `Choreographer` 的 doFrame 到 layout 完成之间：

| 阶段                           | 耗时            | 说明                                                                  |
| ---------------------------- | ------------- | ------------------------------------------------------------------- |
| doFrame → 第一个 `Content()` 执行 | **190～286ms** | Compose 运行时初始化：Recomposer、快照系统、`AndroidComposeView`、Miuix 主题相关类首次加载 |
| `StatusCardHost` 首组合         | 54～56ms       | `MiuixTheme` + `Card` + `AndroidView`                               |
| `HyperGlassBarView` 首组合      | 62～88ms       | 玻璃底栏                                                                |
| `MiuixDropdownHost` 首组合      | 19ms          |                                                                     |
| `MiuixNumberPickerHost` 首组合  | 14～16ms       |                                                                     |
| 4 个 ScrollView `onMeasure`   | 100～110ms     | 三页内容（352 个 View）测量                                                  |
| 其余 layout 收尾                 | 76～111ms      | 顶栏、底栏、insets 应用                                                     |

AOT 之后同一段只剩约 120ms（组合初始化 ~32ms、四个宿主首组合 40～50ms、  
measure/layout 40ms），也就是说 **debug 包把 Compose 首帧放大了 4 倍**。

---

## 4. 根因排序

1. **debuggable=true → ART 不 AOT（占绝对大头，×3）**  
   `status=run-from-apk`，Compose 那几百个类全部解释执行 + JIT，  
   首帧 500ms 里有 400ms 是这件事的代价。
2. **首帧一次性初始化 4 个 Compose 宿主**  
   `StatusCardHost`、`HyperGlassBarView`、`MiuixDropdownHost`、  
   `MiuixNumberPickerHost` 各自独立 `AbstractComposeView`，各有一份  
   Recomposer；两个弹窗宿主启动时根本用不到。
3. **三页 Java View 树全量预构建**  
   352 个 View（设置页 252）在 `onCreate` 里同步建完；AOT 下 24ms，  
   debug 下 152ms。
4. **零碎的 14ms 级开销**  
   `Cfg.get()`（SharedPreferences 首次解析）、`super.onCreate` 的 51ms。

---

## 5. 建议（按性价比）

| 措施                                                                    | 预期收益（AOT 包）      | 风险/成本                   |
| --------------------------------------------------------------------- | ---------------- | ----------------------- |
| 日常装 `fast`（或 release）包，不再装 debuggable 包                               | 首帧 720ms → 190ms | 已加 `fast` buildType，零风险 |
| 加 Baseline Profile（`androidx.profileinstaller` + `baseline-prof.txt`） | 通常再省 15～30% 首帧   | 中，需要采集 profile          |
| 延迟构建设置页/关于页（首次进入再建）                                                   | 省 20～40ms        | 中，需处理「首次进入本页」的那一下卡顿     |
| 延迟创建两个弹窗宿主（首次弹窗再建）                                                    | 省 15～35ms        | 低～中，改动小但要测弹窗首次打开        |
| `Cfg.get()` 挪到后台线程 / 缓存预热                                             | 省 7～14ms         | 低                       |

**不建议**为了启动速度改 `TopBar` / 玻璃底栏的绘制逻辑：GPU 侧不是瓶颈。

---

## 6. 复现命令

```bash
# 冷启动耗时 + 帧统计
adb shell am force-stop io.github.zpan2327.hyperhand
adb shell dumpsys gfxinfo io.github.zpan2327.hyperhand reset
adb shell am start -W -n io.github.zpan2327.hyperhand/.MainActivity
adb shell dumpsys gfxinfo io.github.zpan2327.hyperhand

# 确认包是否被 AOT
adb shell dumpsys package io.github.zpan2327.hyperhand | grep -m2 -E "flags=\[|\[status="
# debuggable 包：flags=[ DEBUGGABLE ... ] + status=run-from-apk
# 非 debuggable：flags=[ HAS_CODE ... ] + status=speed（可用 pm compile -m speed -f 手动触发）

# 构建自用包
./gradlew :module:assembleFast      # module-fast.apk（非 debuggable，debug 签名，可覆盖安装）
```
