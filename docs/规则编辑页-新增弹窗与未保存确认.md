# 规则编辑页：新增走弹窗选择 + 未保存退出确认

> 2026-11-27 / 3.4.6。本文只讲本轮交互改动；首页（长按菜单、隐藏运行状态入口）见 CHANGELOG。

## 1. 为什么要改

三处都是「先斩后奏」的操作：

| 位置 | 改之前 | 问题 |
|---|---|---|
| 「添加触发按键」 | 点一下就往列表尾部塞一条 `音量加 · 短按` | 用户还得再点开这一行改成自己要的键位/按压方式，等于两步 |
| 「添加执行动作」 | 同上，塞的还是 `音量加 · 短按` + `保持原功能` | 同上，动作也得再点一次改 |
| 退出编辑页 | 顶栏返回 / 系统返回直接 `finish()` | 改了一堆条件、动作，手滑返回就全没了，没有任何提示 |

## 2. 现在的行为

### 2.1 添加触发按键

点「添加触发按键」→ 弹 `添加触发按键` 对话框：

- 两组单选：**物理按键**（音量加 / 音量减）、**按压方式**（短按 / 长按 / 双击 / 连按）；
- 摘要实时跟着选择变：`按下「音量减键 · 双击」时执行`；
- 底部 `取消` / `添加`。**只有点「添加」才往草稿里追加**，取消不留任何痕迹；
- 每次打开都从 `音量加 · 短按` 开始，不记住上次的选择，避免误加。

### 2.2 添加执行动作

点「添加执行动作」→ 弹 `添加执行动作` 对话框：

- 一组单选：动作列表（保持原功能 / 下一首 / 上一首 / 播放 / 暂停 / 播放暂停）；
- 一条映射是「触发 + 动作」的整体，所以新增动作行必然要带一条触发：这里**沿用列表最后一条映射的按键与按压方式**（列表为空时用 `音量加 · 短按`）；
- 摘要把这件事写明：`将同时新增「音量减键 · 双击」的触发，加完可以点该行再改`；
- 底部 `取消` / `添加`，同样确认后才追加。

### 2.3 未保存退出

- 进页面时把草稿序列化成 JSON 存一份**快照**（`baselineJson`）；
- 每次重组用当前草稿的 JSON 和快照比，不一致即为「有未保存改动」；
- 顶栏返回与系统返回键走**同一条判断**（`requestExit`）：
  - 干净 → 直接返回；
  - 脏 → 弹 `放弃修改？`：正文「当前修改还没有保存，退出后会丢失。」，按钮 `取消` / `退出`；
    - `取消` → 只关对话框，留在本页，草稿原样保留；
    - `退出` → 不写任何数据，直接 `finish()`；
- 点「保存」仍然直接返回，不弹窗（保存路径不经 `requestExit`）。

## 4. 几个容易踩的点

1. **弹窗必须挂进 `MiuixPopupHost`**：`SkDiscardChangesDialog` 放在 `SmartKeyScaffoldContent` 里，
   和页面内容同一个 Scaffold；放到 Scaffold 外面会渲染不出来。
2. **`overlayOpen` 要包含新增弹窗**：底部「保存」按钮在弹窗打开时会被收起来（避免压住对话框按钮），
   新增的两个对话框也必须算进这个判断，否则保存按钮会盖在对话框上。
3. **返回键的归属**：`BackHandler(enabled = !leaveConfirm.value)`——确认框开着时把返回键让给 Miuix，
   由它的 `onDismissRequest` 关闭；否则会出现「按返回直接把页面退掉、对话框还挂着」。
4. **dirty 用 JSON 比**：条件、映射都是列表，逐字段比容易漏；`Rule.toJson()` 已经存在（存档用），直接复用。
5. **顶栏返回和系统返回必须同一个入口**：`onBack = { requestExit() }`，否则两条路径行为不一致。
